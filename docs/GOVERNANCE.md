# Braidly — Failure-Mode Governance (Rules We Implement)

> **What this is:** the distilled, implementable instructions from two research documents
> the founder provided: *"The Architecture of Failure: A Comprehensive Analysis of Vibe-Coded
> Application Breakdowns"* (PDF) and *"Why Vibe Coded Apps Fail"* (reference catalog, 2026 ed.).
> These are hard rules the **Braidly platform itself** must enforce so the apps built
> through it don't repeat the documented failure modes.
>
> **The one-line insight:** vibe-coded apps fail in layers — security, architecture,
> maintainability, integration, operations, human process — because AI code is probabilistic,
> context-blind, and naive about adversaries. The industry's proven mitigation is
> **Specification-Driven Development (SDD) with constitutional constraints**: a
> machine-readable, version-controlled spec as the single source of truth, with
> non-negotiable security rules embedded. **Our contract-first architecture already IS SDD**
> (`Intent → Spec → Plan → Tasks → Code`). This document hardens it into enforceable rules.

## Why this is our product's moat

The research documents why raw vibe coding is failing commercially and technically:
~45% of AI-generated code carries OWASP Top 10 vulnerabilities (Veracode), only ~10.5% of
agent outputs are both functional *and* secure (CMU SUSVIBES), iterative "fixing" makes
code *more* vulnerable (+37.6% after 5 iterations — IEEE-ISTAS), and hallucinated packages
enable real supply-chain attacks (slopsquatting). The famous Lovable incident
(CVE-2025-48757 — any free-tier user could read any other user's source code) is a
platform-level BOLA failure.

**Our position:** Braidly is the layer that makes vibe coding *verifiable* — the exact
governance gap the industry says is missing. This doc is the enforcement spec for that
position.

## A. The Security Constitution (enforced in every `contract.json` + contract tests)

Every contract generated by the PRD Factory embeds these rules; the contract tests and the
AI Tech Lead verify them **mechanically**, not by asking nicely.

| # | Rule | Failure mode it kills (source) |
|---|------|-------------------------------|
| A1 | **Parameterized queries only.** No string-concatenated SQL/NoSQL anywhere in the module. | SQLi / NoSQLi (both docs) |
| A2 | **No weak password storage.** Plain text, MD5, SHA-1 → reject. Argon2id-class only. | Broken auth (both docs) |
| A3 | **Ownership checks on every object access.** Every `GET/PUT/DELETE /api/:id` requires server-side authorization (never frontend-only). User A can never read/modify User B's data. | IDOR / BOLA — the Lovable incident (both docs) |
| A4 | **Input validation on every route.** Malformed input → 400, never a crash or 500. | Injection, input-validation failures (both) |
| A5 | **No secrets in code.** Scans reject hardcoded keys, committed `.env`, keys in frontend JS. | Exposed secrets (both docs) |
| A6 | **No verbose error leakage.** Production errors return generic messages; stack traces, SQL, and internal paths never reach the client. | Information disclosure (both docs) |
| A7 | **File uploads validated.** MIME whitelist + size limits; uploaded files never served from the web root. | Uncontrolled uploads (both docs) |
| A8 | **CORS origin allowlist.** Never `*` on sensitive endpoints. | Overly permissive CORS (doc 2) |
| A9 | **Security headers + cookies.** CSP present; session cookies `HttpOnly` + `Secure`; CSRF tokens on state-changing forms. | XSS / CSRF (doc 2) |
| A10 | **Rate limiting on auth endpoints** + account lockout after repeated failures. | Brute force (doc 2) |

## B. Supply-Chain Rules (slopsquatting protection)

| # | Rule | Why |
|---|------|-----|
| B1 | **Dependency whitelist in `contract.json`.** These are the ONLY packages a module may import. | Stops hallucinated deps at the gate |
| B2 | **No package installed unless it is (a) on the whitelist, (b) verified to exist on the real registry, (c) pinned to an exact version** (no `^`, no ranges). | ~19.7% of LLM-recommended packages don't exist (USENIX 2025); version drift breaks apps (doc 2) |
| B3 | **PRD Factory must verify a package exists on the registry *before* putting it in a whitelist.** | Pure fabrications = 51% of hallucinations |
| B4 | **A module that installs anything off-whitelist fails verification.** The AI Tech Lead never resolves a dependency by "trusting" the AI's suggestion. | Slopsquatting attack chain |

## C. Anti-Dark-Logic Rules (no comprehension debt)

| # | Rule | Why |
|---|------|-----|
| C1 | **No error-masking.** Empty catch blocks, bare null-swallowing (`?.` chains that hide failures), `catch (e) {}` → rejected by static checks. | Error-masking constructs up +47% (GitClear) — code that "lies about its own health" |
| C2 | **Every catch must log or rethrow.** Silent failure is a violation. | Black Box Effect; up to 80% "Dark Logic" |
| C3 | **Duplication scan at submission.** Orchestrator flags 5+ line block duplicates; above threshold → bounced to owner for refactor. | Block duplication +81%, copy/paste +41% (GitClear) |
| C4 | **Structure is defined in the brief** (routes / services / storage split). No god-objects. | No separation of concerns (doc 2) |
| C5 | **Every module ships a mental-model README** (what it does, entry points, how it fails). Orchestrator verifies it exists and is non-empty. | Comprehension debt; "haunted codebases"; nobody can page the AI at 3 AM |

## D. Test Rules (no happy-path-only testing)

| # | Rule | Why |
|---|------|-----|
| D1 | **Contract tests include negative tests:** unauthorized access → 401/403; malformed input → 400; missing required fields rejected. | "No negative test cases" gap (doc 2) |
| D2 | **Security assertions in contract tests:** secret scan, headers present, auth enforced, no `*` CORS. | Security failures are silent; tests are the detector |
| D3 | **Definition of Done requires negative + security tests to pass**, not just the happy path. | AI builds features, not test suites (doc 2) |
| D4 | **After ANY fix (human or AI), the FULL test suite re-runs.** No partial verification. | Refactoring Drift silently drops security invariants (IEEE-ISTAS) |

## E. AI Tech Lead / Orchestrator Rules (no refactoring drift, no haunted codebases)

| # | Rule | Why |
|---|------|-----|
| E1 | **Minimal-diff fixing.** The orchestrator makes the smallest targeted patch possible. Whole-module rewrites are forbidden unless the contract requires it. | Iteration increases vulnerabilities +37.6% after 5 rounds (IEEE-ISTAS); rewrites discard security invariants |
| E2 | **Bounded fix loop (≤ 3 attempts), every attempt logged** with the error, the patch, and the result. | Unbounded AI fixing = exponential vulnerability growth |
| E3 | **The integration report is the audit trail.** Per-module pass/fail, what was fixed, what was verified. No silent auto-fixes. | "No observability means no recovery" (doc 2) |
| E4 | **Contract freeze during build.** Once coding starts, `contract.json` is immutable until all modules pass. Changes go through the PRD Factory and re-issue every brief. | Scope creep / Feature Accretion (IEEE-ISTAS; doc 2) |
| E5 | **The AI Tech Lead receives the full context** — shared contract, constitution, all briefs, repo conventions — before integrating. | Context Window Decay (doc 2); Context Engineering (research doc) |

## F. Human-Process Rules (the meta-layer)

| # | Rule | Why |
|---|------|-----|
| F1 | **Human review gate.** Modules touching auth, payments, data access, or user input are flagged for founder review before final integration. | The docs' own key takeaway: "Every piece of AI-generated code that touches auth, payments, data access, or user input deserves human review before it ships." |
| F2 | **Shared conventions live in the shared contract** (naming, file layout, error format) — identical for every member. | "No shared conventions across team members" → merge hell (doc 2) |
| F3 | **No ad-hoc prompts mid-build.** New feature requests during coding go through a new discussion → new briefs cycle. | Scope creep; "features built correctly but not what was needed" (doc 2) |
| F4 | **The platform never feeds proprietary code to training-tier free APIs** (e.g., AI Studio). | Shadow AI / IP leakage (research doc) |
| F5 | **Mandatory doc updates after every session.** After every session or significant change, `docs/history.md`, `docs/checklist.md`, and `docs/PROJECT.md` MUST be updated with what was done, decisions made, and current status. Non-negotiable. | Prevents context loss across sessions; ensures any AI tool can resume work. |

## Implementation impact (what changes in our build)

1. **`contract.json` schema gains:** `securityConstitution` (rules A1–A10), `allowedDependencies` (exact versions), `structure` (module layout).
2. **PRD Factory outputs:** the constitution + whitelist + negative-test spec in every brief.
3. **Contract-test generator produces:** happy-path + negative + security assertion tests.
4. **Orchestrator gains:** static checks (C1, C2), duplication scan (C3), registry verification (B2), minimal-diff policy (E1), bounded logged loop (E2), full re-test after every fix (D4), integration report (E3).
5. **DoD checklist per member adds:** negative tests pass, security tests pass, no off-whitelist deps, mental-model README present.
6. **UI/UX stance (from the research's commercial section):** our proof app and platform UI must not ship "No data yet" dead ends — empty states are conversion surfaces; differentiate beyond default template styling. (Adds to Stage-1 design notes.)
